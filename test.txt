SECTION 1 — AUTH ROUTES (/api/auth)
───────────────────────────────────────────────────────────────

TEST 1.1 — Register (Normal User)
----------------------------------
Method : POST
URL    : http://localhost:5000/api/auth/register
Body   :
{
  "username": "adilhassan",
  "email": "adil@test.com",
  "password": "test1234"
}
Expected Status : 201
Expected Body   :
{
  "token": "<jwt_token>",
  "user": {
    "id": "<mongodb_id>",
    "username": "adilhassan",
    "email": "adil@test.com",
    "role": "user"
  }
}
Notes: Copy the token — you will need it later.


TEST 1.2 — Register (Duplicate Email)
---------------------------------------
Method : POST
URL    : http://localhost:5000/api/auth/register
Body   :
{
  "username": "adil2",
  "email": "adil@test.com",
  "password": "test1234"
}
Expected Status : 500 (MongoDB duplicate key error)
Notes: This confirms unique email constraint is working.


TEST 1.3 — Register (Missing Fields)

TEST 2.2 — Upload Video (Authenticated)
-----------------------------------------
Method  : POST
URL     : http://localhost:5000/api/videos
Headers : Authorization: Bearer <your_token>
Body    : form-data (NOT raw JSON)
  Key: video      | Type: File | Value: select any .mp4 file
  Key: thumbnail  | Type: File | Value: select any .jpg file
  Key: title      | Type: Text | Value: My First Video
  Key: description| Type: Text | Value: This is a test video
  Key: genre      | Type: Text | Value: Technology
Expected Status : 201
Expected Body   :
{
  "_id": "<video_id>",
  "title": "My First Video",
  "videoUrl": "https://res.cloudinary.com/...",
  "thumbnail": "https://res.cloudinary.com/...",
  "owner": "<user_id>",
  "views": 0,
  "isPublished": true
}
Notes: Copy the _id — needed for tests below.


TEST 2.3 — Upload Video (No Token)

SECTION 5 — ADMIN ROUTES (/api/admin)
───────────────────────────────────────────────────────────────

SETUP BEFORE THESE TESTS:
1. Go to MongoDB Atlas
2. Open your database → users collection
3. Find your user document
4. Edit: change role from "user" to "admin"
5. Save
6. Login again (Test 1.4) to get a fresh token with admin role
7. Use this new token for all admin tests below
